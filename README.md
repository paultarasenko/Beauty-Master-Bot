# Beauty Master Bot

[![Tests](https://github.com/paultarasenko/Beauty-Master-Bot/actions/workflows/tests.yml/badge.svg)](https://github.com/paultarasenko/Beauty-Master-Bot/actions/workflows/tests.yml)

Telegram-бот для записи к бьюти-мастеру. Клиент сам выбирает услугу, дату и время и
записывается без переписки; мастер управляет расписанием, услугами, контентом и клиентами
через админ-панель в том же боте.

Вся логика детерминированная (без AI/LLM), данные хранятся в PostgreSQL.

Принятые архитектурные решения описаны в [ARCHITECTURE.md](./ARCHITECTURE.md).

## Возможности

### Для клиента

- **Запись**: услуга → дата (до трёх месяцев вперёд) → время → подтверждение. Показываются
  только реально свободные слоты с учётом длительности услуги и «буфера» после неё.
- **Мои записи**: просмотр, отмена и перенос. Перенос безопасен: старая запись отменяется
  только если новый слот удалось занять.
- **Проверить время**: картинка с занятостью выбранного дня и быстрый переход к записи.
- **Услуги и цены**, **портфолио** (фото с описанием), **о мастере**, **как найти**
  (адрес и ориентир), **связь с мастером**.
- **Отзывы**: оценка 1–5 и текст, постраничный просмотр, редактирование своего отзыва.
- **Напоминания**: за 24 часа (с кнопками «Всё в силе» / «Отменить») и за 2 часа до визита.
- **Ссылка-приглашение**: если мастер записал клиента вручную, клиент открывает ссылку
  `t.me/<бот>?start=inv_...`, и запись привязывается к его аккаунту.

### Для мастера (`/admin`)

- **Расписание**: рабочие часы по дням недели и выходные — кнопками.
- **Записи**: список на неделю / месяц / три месяца, ручное добавление записи (в том числе
  для человека, которого нет в боте, — с формированием ссылки-приглашения), удаление записи,
  закрытие и открытие времени (блокировки).
- **Услуги и цены**: добавление, переименование, цена, описание, длительность,
  свободное время после услуги, включение/выключение.
- **Портфолио, «Обо мне», приветствие, отзывы** (удаление): всё редактируется из бота.
- **Статистика** за сегодня / неделю / месяц / три месяца: число записей, фактический и
  ожидаемый доход, свободные часы. **Excel-отчёт** по записям за период.
- **Личные напоминания**: себе самому, один раз или с повтором (день / неделя / месяц / год).
- **Уведомления**: о новой записи, отмене, переносе, новом пользователе бота, напоминание
  за 2 часа до визита с данными клиента.
- **Профиль клиента**: переключение в клиентское меню, чтобы увидеть бота глазами клиента.

### Лимиты и ограничения клиентов

- У клиента не более **3 одновременных активных записей**. Запись сверх лимита возможна
  только после запроса мастеру: мастер принимает или отклоняет его (с комментарием или без),
  разрешение разовое.
- Если клиент **подряд отменяет 3 записи**, мастер получает предупреждение и может
  ограничить доступ или подтвердить его. Ограниченный клиент не может записываться и
  оставлять отзывы, но может написать мастеру; мастер открывает доступ или ограничивает навсегда.

## Стек

- Python 3.12, aiogram 3.x (async), long polling
- PostgreSQL 16, SQLAlchemy 2.x (async), Alembic
- APScheduler — «тикающие часы» для фоновых задач
- openpyxl (Excel-отчёты), Pillow (картинка расписания)
- Docker / Docker Compose

## Архитектура

```
Telegram handler → service → repository → SQLAlchemy → PostgreSQL
```

Бизнес-логика живёт в `app/services/*`, handlers только принимают апдейт и вызывают сервис.

```
app/
├── bot/
│   ├── handlers/{client,admin}/   # хендлеры по разделам
│   ├── keyboards/                 # клавиатуры и callback data
│   ├── middlewares/               # сессия БД, обработка ошибок, фильтр админа
│   └── states/                    # FSM-состояния
├── database/{models,repositories}/
├── services/                      # бизнес-логика (записи, слоты, отчёты, лимиты)
├── scheduler/                     # воркер напоминаний и завершения записей
├── utils/                         # время, деньги, повторы, картинка расписания
├── config/                        # pydantic-settings
└── seed.py                        # тестовые данные
alembic/                           # миграции
tests/                             # pytest на реальной PostgreSQL
```

### Ключевые решения

- **Защита от double booking на уровне БД**: GiST exclusion constraint по времени
  подтверждённых записей. Проверено тестом на реальной гонке двух параллельных запросов.
- **Напоминания переживают рестарт**: хранятся в таблице `notifications`, а не в памяти.
- **Snapshot услуги**: запись хранит название, цену и длительность на момент создания.
- **Режим админа** (панель / клиентское меню) хранится в БД и переживает рестарт.
- Записи, время которых прошло, автоматически переводятся в статус «выполнена».

## Конфигурация

Переменные окружения (файл `.env`, шаблон — `.env.example`):

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | токен от [@BotFather](https://t.me/BotFather) | обязательна |
| `ADMIN_TELEGRAM_ID` | числовой Telegram ID мастера ([@userinfobot](https://t.me/userinfobot)) | обязательна |
| `DATABASE_URL` | строка подключения (`postgresql+asyncpg://...`) | localhost:5432/beauty_bot |
| `TIMEZONE` | часовой пояс по умолчанию (IANA) | `Europe/Minsk` |
| `SLOT_INTERVAL_MINUTES` | шаг сетки времени | `30` |
| `REMINDER_HOURS_BEFORE` | за сколько часов слать первое напоминание | `24` |
| `REMINDER_POLL_INTERVAL_SECONDS` | период проверки фоновых задач | `60` |

Часовой пояс мастера, заданный в профиле (`master_profile.timezone`), приоритетнее `TIMEZONE`.

## Запуск (Docker)

```bash
cp .env.example .env      # заполните BOT_TOKEN и ADMIN_TELEGRAM_ID
docker compose up --build
```

Миграции применяются автоматически при старте контейнера `bot`
(`docker-entrypoint.sh` → `alembic upgrade head` → запуск бота).

Первичные данные можно ввести через `/admin` или залить тестовые:

```bash
docker compose exec bot python -m app.seed
```

## Запуск без Docker (разработка)

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt

# PostgreSQL должен быть запущен, БД создана
cp .env.example .env      # DATABASE_URL на localhost, BOT_TOKEN, ADMIN_TELEGRAM_ID
alembic upgrade head      # расширение btree_gist создаётся миграцией
python -m app.seed        # опционально
python -m app.main
```

## Тесты

```bash
docker compose -f docker-compose.test.yml up -d --wait   # PostgreSQL на localhost:5434
pip install -r requirements-dev.txt
pytest tests/ -v                                          # миграции накатываются автоматически
docker compose -f docker-compose.test.yml down
```

Своя БД: переменная `TEST_DATABASE_URL`. Имя БД обязано оканчиваться на `_test` — тесты
очищают таблицы. Без доступной БД pytest сразу завершится с подсказкой.

Покрыто: расчёт слотов, создание/отмена/перенос записей, реальная гонка за один слот,
напоминания и их поведение после рестарта, лимиты и ограничения клиентов, приглашения,
статистика и отчёты, повторы личных напоминаний, часовые пояса, миграции.

## Production

- Задайте боевые `BOT_TOKEN`, `ADMIN_TELEGRAM_ID`, `TIMEZONE` в `.env`; файл `.env` не коммитьте.
- Смените пароль PostgreSQL (в `docker-compose.yml` по умолчанию `postgres`/`postgres`).
- Порт `5433` в `docker-compose.yml` пробрасывает PostgreSQL на хост. На сервере уберите
  проброс или привяжите к localhost (`127.0.0.1:5433:5432`). Боту входящие порты не нужны.
- Настройте регулярный backup (ниже).
- Логи — в stdout контейнера: `docker compose logs -f bot`.

## Backup

```bash
docker compose exec -T postgres pg_dump -U postgres beauty_bot > backup_$(date +%Y%m%d).sql
```

Восстановление:

```bash
cat backup_YYYYMMDD.sql | docker compose exec -T postgres psql -U postgres beauty_bot
```

## Известные ограничения

- Один мастер на экземпляр бота.
- Состояния диалогов (FSM) хранятся в памяти: при рестарте незавершённый ввод сбрасывается.
- Валюта в сообщениях зафиксирована как BYN.
- Перерывы в течение дня учитываются при расчёте слотов, но управления ими из бота нет.
- Статус `no_show` автоматически не выставляется.
